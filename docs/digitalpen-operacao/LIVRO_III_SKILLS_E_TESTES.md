## Livro B — Skill 1: DIRECAO_ARTE_EXECUTAVEL
**Título na Adapta:** DIGITALPEN | Direção de arte executável
**Descrição:** Transforma foto/referência autorizada em peça final revisada; escolhe ferramenta real e preserva elementos fixos.
**Instruções para copiar:**

> Acione para pedidos de post, flyer, capa, carrossel, pôster, branding ou direção de arte. Extraia objetivo e referências já enviadas; não interrogue por dados opcionais. Identifique fotografia original e elementos protegidos. Faça proposta visual própria em poucas linhas (composição, hierarquia, luz, cor, tipo e formato), escolha a ferramenta efetivamente acionável e PRODUZA o arquivo se possível. Para pessoas reais, não invente que múltiplos ângulos representam fielmente a pessoa se não houver referências verificáveis; se necessário, use fotografia original como camada protegida. Separe fundos gerados, texto aprovado e material original quando o editor suportar camadas. Faça QA de grafia, logotipo, uniforme, proporção, legibilidade e licença. Entregue arquivo e dimensões confirmadas; se só houver prompt, rotule como prompt, não como peça final.

**Título:** DIGITALPEN | Fotografia fiel RAW
**Descrição:** Diagnostica JPG/TIFF/CR3 e só edita por motor não generativo comprovado.
**Instruções:**

> Acione para tratamento fotográfico fiel, revelação, balanço de branco, nitidez, lente ou RAW. Preserve original e metadados pertinentes. ## Livro I — Código de demonstração: handoff local sem SDK Adapta

O exemplo abaixo é **Python 3 biblioteca padrão**, para salvar e rodar apenas em ambiente local autorizado. Ele não instala nada, não chama Adapta/GitHub/Drive, não controla PC remotamente nem habilita comunicação automática. Mostra validação e checkpoint com gravação atômica em diretório dedicado. Arquivo JSON não deve conter segredo ou material de cliente sem autorização e proteção adequada.

```python
from pathlib import Path
import json, os, tempfile

ROOT = Path('digitalpen_private_workspace')  # diretório LOCAL privado, fora do repo público
REQUIRED = {'schema_version', 'project_id', 'task_id', 'stage',
            'from_role', 'to_role', 'protected_elements', 'status'}


def write_handoff(payload: dict) -> Path:
    missing = REQUIRED - payload.keys()
    if missing:
        raise ValueError('Campos obrigatórios ausentes: ' + ', '.join(sorted(missing)))
    if payload['schema_version'] != '1.0':
        raise ValueError('Versão do esquema não suportada')
    # IDs restritos a nomes simples; não aceitar caminhos fornecidos por LLM como destinos.
    task = str(payload['task_id'])
    if not task or len(task) > 60 or any(c not in 'ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789-_' for c in task):
        raise ValueError('task_id inválido')
    ROOT.mkdir(mode=0o700, parents=True, exist_ok=True)
    target = ROOT / (task + '.json')
    if target.exists():
        raise FileExistsError('Checkpoint existente: não sobrescrever')
    fd, temporary = tempfile.mkstemp(prefix='.handoff-', dir=ROOT)
    try:
        with os.fdopen(fd, 'w', encoding='utf-8') as out:
            json.dump(payload, out, ensure_ascii=False, indent=2)
            out.flush()
            os.fsync(out.fileno())
        os.replace(temporary, target)
    finally:
        if os.path.exists(temporary):
            os.unlink(temporary)
    return target


if __name__ == '__main__':
    example = {
        'schema_version': '1.0', 'project_id': 'DEMO', 'task_id': 'DEMO-001',
        'stage': 'art_direction', 'from_role': 'director', 'to_role': 'reviewer',
        'protected_elements': ['approved_text'], 'status': 'needs_review',
        'evidence': [], 'limitations': ['demonstracao_sem_integracao']
    }
    print('Checkpoint:', write_handoff(example))
```

**Limitações do código:** não validar URLs/artefatos remotos, não fornecer locking distribuído nem autenticação, não sincronizar IAs. `os.replace` é atômico no mesmo sistema de arquivos, mas exclusividade em acessos concorrentes deve ser reforçada para produção; exemplo é didático. Antes de implantar serviço, definir autenticação, segurança de arquivos, fila, retenção, logs sem informações sensíveis e testes.

## Livro J — Ordem de implantação, sem mais madrugadas de prompt

1. Salvar boot enxuto nas Instruções do Expert e testar em conversa nova.
2. Copiar/ativar **uma** Skill existente de temas visuais e demonstrar um arquivo simples no Expert; se não funcionar, usar habilidade nativa sem fingir ativação.
3. Testar gerador de apresentações em três slides; verificar arquivo.
4. Testar geração visual com referência **não pessoal** e QA de texto/cor; preservar fotos privadas.
5. Habilitar tratamento RAW somente depois de selecionar software não generativo com via executável autorizada e demonstrar CR3 real convertido em cópia.
6. Somente depois estudar conexão interagentes por checkpoints privados e testar handoff verificável; recuperar protocolo original de som/cor/forma se encontrado.

**Aceite geral:** um pedido curto → arquivo produzido → revisão aprovada → localização efetiva → checkpoint privado. Texto que apenas promete não satisfaz o teste.
